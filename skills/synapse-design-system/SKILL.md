# Synapse design system

Audit the existing styles, tokens, and primitives before adding anything. Introduce a token only for a recurring semantic role, not a one-off visual value. Build components around states and accessibility first, then add variants that correspond to real product needs.

Read [frontend baseline](../../references/frontend-baseline.md). If the user wants a new visual direction, identify the existing surfaces it should govern and articulate the token contract before changing individual components. Do not replace a working styling system wholesale unless explicitly requested.
